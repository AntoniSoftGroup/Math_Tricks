# Облачный прогресс iOS и Android

В iOS: «Настройки → Облачный прогресс». Вход через Apple или Google, ручное сохранение/восстановление и автоматическая синхронизация используют существующий Firebase-проект `api-project-162088319865`.

В правой части заголовка настроек находится кнопка «Войти», как в Android. Она открывает окно выбора с официальными кнопками Apple и Google и отменой. После входа кнопка показывает имя аккаунта и открывает облачный профиль. На экране облачного прогресса кнопка «Войти» открывает то же окно. `SettingsViewController.buildContent/updateCloudButton` обновляют кнопку при смене аккаунта; `CloudSignInViewController.show/choose` закрывают выбор перед системной авторизацией, `CloudViewController` использует общий выбор. Подпись «Войти» локализована в `Resources/*/Interface.strings (`cloud.*`)` по строкам Android.

## Что настроить на сайтах

1. В [Firebase Console](https://console.firebase.google.com/project/api-project-162088319865/authentication/providers) открой Authentication → Sign-in method. Проверь, что Google включён. Для iOS зарегистрировано приложение `com.antoni.mathtricks.free`; его `GoogleService-Info.plist` и схема возврата Google уже подключены в проекте.
2. В [Apple Developer](https://developer.apple.com/account/resources/identifiers/list) открой App ID `com.antoni.mathtricks.free` команды `J2G688FEXG`. Включи Sign in with Apple. Capability и entitlement в Xcode уже добавлены; профиль подписи должен поддерживать эту возможность.
3. В Apple Developer создай Services ID для Firebase Auth и свяжи его с этим App ID. Для веб-конфигурации укажи домен `api-project-162088319865.firebaseapp.com` и Return URL `https://api-project-162088319865.firebaseapp.com/__/auth/handler`.
4. Создай ключ Sign in with Apple, связанный с этим App ID. Сохрани Key ID и файл `.p8`. В Firebase → Authentication → Apple включи провайдер, укажи Services ID, Team ID `J2G688FEXG`, Key ID и приватный ключ в OAuth code flow configuration. Ключ хранится в Firebase; в приложение и Git его добавлять нельзя. Эта настройка нужна также для отзыва токена при удалении Apple-аккаунта. [Инструкция Firebase](https://firebase.google.com/docs/auth/ios/apple).
5. В Firestore → Rules оставь предоставленные правила с пятью документами `current`, `level_statistics`, `trick_statistics`, `example_statistics`, `trick_level_statistics`. Приложение пишет их одной транзакцией: `schemaVersion=1`, общая `revision`, `updatedAt=serverTimestamp`. Правила из приложения не публиковались.

Если для Firestore/Auth уже включено обязательное App Check, понадобится отдельно подключить провайдер iOS: эта интеграция его не настраивает. Private email relay нужен, если проект отправляет письма Firebase пользователям со скрытым Apple email; текущий вход писем не отправляет.

## Как переносить прогресс

- Уже есть Android-прогресс: на iPhone войди через тот же Google.
- Сначала вошёл через Apple: на iPhone нажми «Связать с Google», подтверди связывание и выбери Google. После этого на Android войди через этот Google.
- Сначала вошёл через Google: можно добавить Apple кнопкой «Связать с Apple».

Связывание использует `currentUser.link(with:)`, сохраняя Firebase UID. Перед связыванием есть отдельное согласие на объединение данных для входа. Приложение не объединяет аккаунты по совпадению email. Если способ входа уже занят другим Firebase-аккаунтом, будет сообщение; чужой прогресс не перезаписывается. [Документация связывания](https://firebase.google.com/docs/auth/ios/account-linking).

Выход оставляет локальный прогресс и выключает синхронизацию. При смене Firebase UID используются раздельные локальные профили. Первый вход принимает гостевой прогресс устройства. Если балансы отличаются и изменены обе стороны, пользователь выбирает целиком баланс и открытия за монеты. Монеты не складываются; остальные данные объединяются по правилам Android.

## Формат и ограничения

Основной документ содержит ровно восемь полей прогресса Android: `coins`, `records`, `levels`, `byHeartLevels`, `byHeartUnlocked`, `coinUnlocks`, `stats`, `graphs`. Статистика уровней передаётся строкой; графики, группы трюков, отдельные примеры и подробные уровни — gzip + Base64. Подробные уровни облака ограничены 1–10, как в текущем Android; более высокие уровни остаются в локальном прогрессе и файле. Отметка `statisticsResetAt`/`resetAt` не даёт старым устройствам возвращать очищенную статистику.

Размер проверяется по фактически отправляемым строкам после сжатия. Предупреждение появляется от 80% любого лимита: основной прогресс 685 000 байт JSON, графики 600 000 символов Base64 / 20 000 точек / 2 000 000 байт после распаковки, дополнительные документы 1 044 480 байт каждый. Проверяются также ограничения распаковки. После закрытия диалога предупреждение остаётся на экране облака. Повторный диалог не появляется до освобождения места ниже 80%.

Единый экран «Настройки → Облачный прогресс» содержит две карточки: облако и файловые копии. «Сохранить резервную копию в файл» создаёт совместимый `.mathtricks.gz` для обеих платформ. «Сохранить полную копию iOS» сохраняет также полную историю сессий и настройки iOS. «Восстановить из файла» принимает оба формата. При превышении лимита транзакция не отправляется, предыдущая облачная копия остаётся. Частичное сохранение с потерей статистики не выполняется.

Автосинхронизация работает на главном экране, в настройках и на экране облака: не чаще раза в 30 секунд после локальных изменений, проверка облака без изменений — раз в 5 минут. Во время игры синхронизация не запускается. Офлайн игра остаётся доступна; облачные транзакции требуют связи и не ставятся в очередь старых записей. Перед восстановлением сохраняется SQLite-копия в `BeforeImport`. Локальный сброс/импорт файла ставит автосинхронизацию на паузу до ручного «Сохранить» или «Восстановить».

Возраст, согласия, покупки, Game Center и настройки интерфейса не передаются в облачные документы. При удалении облачного аккаунта приложение повторно подтверждает вход, очищает пять документов и удаляет Firebase Auth пользователя; для Apple отзывает токен. Существующие правила запрещают `delete`, поэтому пустые служебные документы остаются под недоступным UID. Полное физическое удаление документов требует серверного обработчика с Admin SDK.

## Зависимости и проверка

Добавлены FirebaseAuth и FirebaseFirestore из уже используемого Firebase iOS 13.0.1. GoogleSignIn закреплён на официальном коммите `5140b1e59fffcabdd88da33bd574187af5f1f6d1`: тег 10.0.0 требует AppCheck 11, а Firebase 13 — AppCheck 12; этот коммит Google разрешает обе версии. Локальных исправлений SDK нет. При появлении совместимого релизного тега заменить pin на него.

Код проверяется компиляцией. DEBUG содержит проверки формата, повторного объединения статистики и ограничения подробных уровней. Приложение на устройстве не устанавливалось и не запускалось; реальный вход, связывание, Firestore rules, офлайн-режим, удаление аккаунта и перенос Android ↔ iOS нужно проверить после настройки провайдеров. Рекомендуемый сценарий: сохранить Google-прогресс Android, открыть на iOS, сыграть и сохранить, снова открыть Android; повторить синхронизацию без игры и проверить, что счётчики не растут.

Исправление крэша `Invalid cloud serialization: invalidArchive`: `ArchiveGzip.compress` принимает пустые данные и создаёт корректный gzip-поток. Пустые графики и строки статистики допустимы для облака; распаковка по-прежнему отклоняет пустой вход без gzip-заголовка. В DEBUG-проверке сохранён сценарий сжатия и распаковки пустых данных.
