# Этап 5: общий слой данных

## Доступ из приложения

```text
Экраны / будущая игровая логика
└── AppDataStore (@MainActor, ObservableObject)
    └── ProgressRepository (actor)
        ├── Progress.sqlite — новые данные и изменения
        └── LegacyProgressIndex — проекция исходной Core Data
```

`AppDataStore.prepare()` сначала получает совместимый снимок этапа 4, затем
открывает репозиторий. Несколько окон разделяют одну загрузку и один actor.
Экраны больше не получают `LegacyProgressSnapshot` и не обращаются к Core Data,
UserDefaults или SQLite напрямую. Главная подписана на `$snapshot` через Combine:
монеты и количество решений обновляются после успешных записей, без пересоздания
контроллера. При публикации учитывается revision, чтобы поздно возобновившийся
запрос не заменил более новое состояние.

## Файлы и схема

Старый `Math_Tricks.sqlite` и оригинальные UserDefaults не переписываются.
Новая база расположена рядом, в отдельном подкаталоге:

`Application Support/MathTricksProgress/Progress.sqlite`.

| Таблица | Назначение |
|---|---|
| `metadata` | UUID исходного Core Data-хранилища |
| `app_state` | Типизированное состояние, настройки, монеты, счётчики и рекорды |
| `trick_progress` | Изменённые отметки и новые разблокировки приёмов |
| `level_progress` | Новые / улучшенные результаты и доступность уровней |
| `operations` | ID и точное содержимое уже применённых операций |

Текущая версия задаётся `PRAGMA user_version = 1`. Создание схемы, запись UUID
и первичный перенос состояния выполняются одной транзакцией 0 → 1.
При повторном открытии читается сохранённое состояние, а не заново начисляются
500 стартовых монет или копируются старые значения.

Неизвестная новая версия, посторонние таблицы в версии 0, отсутствие обязательной
записи или несовпадение UUID исходного хранилища приводят к ошибке. Удаления базы,
автоматического сброса или подмены её пустой базой нет. Повреждённый JSON состояния
также не заменяется значениями по умолчанию. Будущие изменения обязательных полей
должны сопровождаться явной миграцией схемы, а не изменением декодера со сбросом.

`ProgressDatabase` использует встроенный SQLite3, связанные параметры запросов,
WAL, synchronous FULL и BEGIN IMMEDIATE / COMMIT / ROLLBACK. Statement всегда
освобождается после выполнения. Дисковые операции изолированы actor-ом;
в UI возвращаются только Sendable-значения. Состояние в памяти публикуется
после COMMIT, поэтому неуспешная запись не изображает успешное начисление.

## Первичный перенос и чтение уровней

Из UserDefaults однократно переносятся монеты, общее количество решений,
текущая / максимальная сложность, длина партии, победы игроков, раскладка,
звук, вибрация, цвет и восемь возможных рекордов. Скорость остаётся в секундах,
очки — в очках; сравнение рекорда скорости выбирает меньшее значение.
Исторические значения сохраняются без сужения до Int16.

`LegacyProgressIndex` сопоставляет ID по карте этапа 4. При чтении уровня
объединяются исходный результат и новая запись: лучшие очки / звёзды выбираются
по максимуму, доступность — по OR. Если в старой базе были дубликаты, это правило
применяется только к проекции; исходные строки остаются нетронутыми. Явная новая
отметка выбранного приёма может переопределять старую отметку.

У заучивания множитель 1–100 и диапазон 1–10 остаются отдельным пространством
ключей; у обычных приёмов сохраняются уровни 1–100. Отсутствующие уровни не
создаются при простом чтении. Начальная доступность нового каталога относится
к этапу его переноса, а не выдумывается из отсутствующих данных.

Исторические графики доступны как значения с исходными датами, score и ID.
Десятые секунды старого графика скорости преобразуются в секунды для чтения.
Неизвестные и некорректно индексируемые старые записи остаются в исходной базе
и резервной копии этапа 4, а не удаляются из неё.

После первого переноса новые скалярные значения в Progress.sqlite являются
текущими. Старые UserDefaults не зеркалируются обратно. Произвольное изменение
старых файлов вне репозитория не является импортом; импорт / восстановление
нужно реализовать отдельной согласованной операцией на этапе 21.

## API

- `updateSettings(_:)` — точечные изменения звука, вибрации, сигнала ошибки,
  раскладки, темы, цвета и размера шрифта. Отдельные окна не перезаписывают
  чужие поля устаревшей копией всех настроек.
- `setCurrentLevel(_:)` — сохранение выбранной доступной сложности.
- `setMultiplayerLength(_:)` — 5–35 шагов с шагом 5, как в Android.
- `setDailyProgress(_:)` — хранение цели, выполненных заданий и серии дней;
  алгоритм ежедневной игры и напоминания здесь ещё не реализуются.
- `setTrickSelected(_:selected:)`, `trickProgress(_:)` — отметки и доступность.
- `levelProgress(_:)`, `levels(scope:parentID:)` — единое чтение старых и новых уровней.
- `historicalGraphs()` — доступ к исходной истории.
- `apply(_:)` — атомарная запись `ProgressOperation`: изменение монет, решённых
  примеров, открытие приёма / сложности, результат уровня, рекорд и победа игрока.

В `AppSettings` сохраняются новые поля Android: сигнал ошибки, системный / ручной
масштаб текста, идентификатор темы и отдельные положения интенсивности по темам.
Финальный интерфейс и алгоритмы изменения этих значений относятся к этапам 6–18.

## Повторные операции

Клиент создаёт стабильный `ProgressOperation.id` один раз для логического действия
и сохраняет его при повторной попытке: например, ID транзакции покупки или
постоянный ID результата партии. Повтор того же ID с тем же содержимым возвращает
текущее состояние без начисления. То же имя с другим содержимым — ошибка.
Новый UUID на каждой попытке не считается повтором старой операции.

Начисление / списание, разблокировка, запись результата и квитанция операции
коммитятся вместе. Недостаток монет, переполнение Int64 и неверные параметры
не меняют состояние. Повторная платная разблокировка уже открытого приёма
также отклоняется. Никакие реальные покупки или награды на этапе 5 не запускаются.

## Ограничения последующих этапов

Облачные аккаунты, подробная статистика попыток, импорт файлов и сброс прогресса
пока не подключены. Их схема вводится отдельными миграциями. При будущем сбросе
нельзя просто удалить новые записи: нужен явный признак игнорирования старого
базового прогресса, иначе он снова появится из Core Data. Экспорт обязан учитывать
обе части логического прогресса, а не только файл новой базы.

Будильник отсутствует. Тестовые кнопки начисления монет и искусственные партии
в пользовательский интерфейс не добавлялись.

## Проверка

Debug-сборка с автоматической подписью успешна. Приложение установлено и запущено
на iPhone 15 Pro Max без предварительного удаления приложения. Лог:
`/tmp/math_tricks_stage5_build.log`.

Автотесты, искусственные базы и пробные операции с пользовательскими монетами
не выполнялись. Реальные сценарии сохранения и повторного открытия пользователь
проверяет по мере подключения экранов. Этап не меняет финальный дизайн меню.

Этап 7: необязательный `AppSettings.themeBaseColorHex` и дополнительные аргументы
`SettingsChange.appearance` сохраняют базовый цвет и все позиции интенсивности
одной транзакцией. Старые JSON без optional-поля читаются без изменения user_version.
Подробнее — [THEMES.md](THEMES.md).

## Текущее расширение после игровых этапов

Актуальная `user_version` — 4. Миграции 1 → 2 → 3 → 4 добавляют
`game_sessions`, `multiplayer_sessions`, `archived_graphs`; старые модели Core Data
не меняются. В заучивании поддерживается 21 уровень Android; старые ключи
сохраняются. Ежедневный движок и напоминания описаны в DAILY_PRACTICE.md.

В новых строках `operations.request` хранится SHA-256 канонического запроса
с префиксом `sha256:`. Это сохраняет проверку повторного ID и не дублирует всю
растущую историю сессии в каждой предыдущей квитанции. Ранние квитанции с полным
JSON по-прежнему читаются и сравниваются без миграции и повторных начислений.

Импорт и сброс сначала создают отдельную SQLite-копию, затем заменяют только
новую проекцию. `generation` отделяет старые игровые экраны от восстановленного
прогресса. После явной замены legacy-проекция помечается отключённой, сами
старые файлы не трогаются. Формат файлового архива описан в LOCAL_ARCHIVES.md.
