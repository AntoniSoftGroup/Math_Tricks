# Этап 3: общая оболочка экранов

## Структура

```text
Math_TricksApp → ContentView (UIViewControllerRepresentable)
└── AppRootViewController
    ├── AppNavigationController
    │   └── Текущий ShellScreenViewController
    └── BannerContainerView — один на всю сцену
```

UIKit-контроллер встроен в существующую точку входа SwiftUI. Он занимает окно,
а его содержимое учитывает safe area: вырезы, статусную строку и нижний индикатор.
У каждой сцены собственные стек и баннер, глобальных singleton для них нет.

## Изменённые и добавленные методы

- `ContentView.makeUIViewController()` создаёт оболочку. `updateUIViewController()`
  не перестраивает её при обновлениях SwiftUI; `Math_TricksApp.body` передаёт ей
  полную область окна.
- `AppRootViewController.viewDidLoad()` добавляет дочерний UINavigationController
  по правилам UIKit containment и размещает отдельный нижний рекламный контейнер.
  `viewDidLayoutSubviews()` обновляет только размер временной рекламной области.
- `AppRouter.start()` устанавливает первый экран только для пустого стека.
  `show()` открывает раздел, не дублирует текущий и умеет вернуться к корню;
  `goBack()` возвращает на предыдущий экран, сохраняя его экземпляр и прокрутку.
  Повторные переходы во время анимации блокируются.
- `AppNavigationController.gestureRecognizerShouldBegin()` разрешает жест возврата
  только при наличии предыдущего экрана. Системный navigation bar скрыт:
  заголовки и кнопки возврата принадлежат экранам.
- `BannerContainerView.showPlaceholder()` показывает временную подпись «Реклама».
  `updatePlaceholderSize()` использует 80 pt в портретной и 70 pt в альбомной
  ориентации. Переход между экранами этот экземпляр не заменяет.
  `setContent(_:height:)` позволяет подключить содержимое с измеренной высотой,
  `collapse()` освобождает место без удаления самого контейнера.
- `ShellScreenViewController.makeHeader()`, `populateContent()` и `addButton()`
  создают временные экраны с доступной кнопкой возврата, прокруткой и Dynamic Type.

## Что доступно для ручной проверки

Главная → Один игрок / Тренировка / Два игрока / Заучивание / Настройки.
Настройки → Оформление позволяет проверить стек глубже одного перехода.
Кнопка «Назад» и жест от левого края возвращают к предыдущему экрану; у корня
кнопки возврата нет. Нижняя область рекламы остаётся общей при всех переходах.
При повороте контроллеры и стек не пересоздаются, содержимое можно прокручивать.

Это временные назначения для проверки оболочки. Финальное главное меню, темы,
игровые экраны и настоящая реклама относятся к следующим этапам. Плейсхолдер
баннера не содержит SDK и рекламных запросов; его размеры не определяют размер
будущей адаптивной рекламы. Контейнер можно полностью свернуть при отсутствии
рекламы или после отключения рекламы покупкой.

Старая Core Data и UserDefaults не открываются и не изменяются. Будильник,
его кнопки, зависимости и разрешения отсутствуют.

## Проверка

- Debug-сборка с автоматической подписью для iPhone 15 Pro Max успешна.
- Приложение установлено и запущено на подключённом iPhone.
- Лог сборки: `/tmp/math_tricks_stage3_build.log`.
- Автотесты не запускались; переходы, жест возврата, поворот и внешний вид
  на устройстве проверяет пользователь.

После исправления этапа 6 `AppRouter.start()` вызывается сразу при создании
оболочки, без ожидания snapshot. `loadProgress()` читает данные асинхронно;
надписи загрузки и спиннера нет. Счётчики появляются после публикации snapshot.
Ошибка чтения показывает общий диалог повтора и не обнуляет прогресс.

По указанию пользователя переходы между экранами выполняются мгновенно:
`AppRouter.show/goBack` используют animated=false для push/pop/возврата на главную.
Стандартный interactive pop сдвига отключён. `AppNavigationController.swipeBack`
сохраняет возврат жестом от края, выполняя мгновенный pop после завершения жеста,
с учётом LTR/RTL. Анимация не следует за пальцем.
