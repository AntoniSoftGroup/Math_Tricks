## Границы работы

- Изменения приложения допускаются только в `ios/Math_Tricks`.
- `android/Math_Tricks` — эталон интерфейса и текущего поведения, только чтение.
- `ios-legacy/Math Tricks Free` — источник старого прогресса и iOS-идентификаторов,
  только чтение.
- Будильник полностью исключён из текущего переноса: кнопка и промо на главной,
  его экраны, задания пробуждения, мелодии, служба, виджет и отдельная база.
  Заготовки и зависимости этого модуля не создаются. Возвращение к нему требует
  отдельного указания пользователя.
- Ежедневные математические задания, серия дней и обычные напоминания остаются
  отдельной функцией. Их Android-реализация использует AlarmManager для доставки
  уведомлений, но это не модуль будильника с заданиями пробуждения.
- Локальные этапы разрешены последовательно без дополнительного подтверждения.
  Большие этапы делятся на самостоятельные подэтапы.
- Автотесты не создаются и не запускаются. После этапов — только BUILD;
  установка и запуск не выполняются даже при подключённом устройстве.
Этап 1 меняет только документацию, новых экранов для проверки не добавляет.

## Общая структура нового iOS

Структура, реализованная на этапе 3:

```text
Корневой контроллер приложения
├── Контейнер навигации
│   └── Текущий дочерний экран
│       └── Вложенное решение / результат / детали, когда нужны
└── Один общий нижний контейнер рекламного баннера
```

- Экраны переключаются внутри оболочки, как фрагменты Android. UIKit-контейнер и
  навигационный стек реализованы; временные назначения заменяются настоящими
  экранами на следующих этапах без переноса баннера внутрь этих экранов.
- Баннер принадлежит оболочке, а не отдельным экранам; обычный переход не должен
  пересоздавать его. Настоящие размеры определяются загруженной рекламой.
- Экран располагается над баннером с учётом безопасной области и поворота.
  Фиксированная пустая полоса на всех экранах не является конечной реализацией.
- Заголовки, кнопки возврата, диалоги, поля и клавиатура воспроизводят Android.
  Системные формы Game Center, покупок и согласия остаются системными iOS.
- Навигация, игровое состояние, доступ к данным и внешние сервисы разделяются.
  Генератор примеров и подсчёт результатов не должны зависеть от UIView.
- При открытии решения или рекламы состояние таймера обрабатывается явно;
  поворот и возврат не создают второй таймер или повторную награду.
- На главной отсутствует исключённая кнопка будильника и его промо; остальные
  блоки сохраняют Android-оформление с естественной перекомпоновкой свободного места.

## Основные переходы

1. Новый пользователь: возраст → первоначальная тема → главное меню. Для старого
   пользователя сначала распознаётся сохранённый прогресс; новые настройки не
   должны повторно запускать старую инициализацию с обнулением данных.
2. Главное меню → одиночные режимы → один из четырёх игровых экранов → результат.
3. Главное меню → каталог приёмов → правило → уровни → игра конкретного приёма.
4. Каталог с отмеченными приёмами → выбор четырёх режимов или подготовка двух
   игроков. Отметки и положение списка сохраняются при возврате.
5. Главное меню → подготовка двух игроков со случайными приёмами → соревнование
   или командная игра. Вариант каталога передаёт выбранные приёмы вместо случайных.
6. Главное меню → заучивание → число → уровень → примеры → игра. Уже доступный
   уровень может запускаться напрямую согласно `ByHeartLevelsFragment`.
7. Главное меню → ежедневная игра; настройки напоминаний → выбор приёмов → назад.
   Уведомление открывает ежедневную игру с сохранённой сложностью.
8. Игра → вложенное решение → таблица умножения → назад к решению / игре.
9. Игра → завершение / следующий уровень → подробности результата → детали
   отдельного приёма или решения. Повторить, продолжить и выйти — разные действия.
10. Главное меню → подробная статистика; рекорды и результаты → соответствующий
    график; кнопки таблиц лидеров → системный Game Center.
11. Настройки → тема / размер текста / раскладка / облако / сброс. Возврат после
    изменения оформления обновляет экран и не сбрасывает прогресс.

`SolutionFragment`, `TimerEndFragment`, `LevelCompleteFragment`,
`MultiplayerWinFragment`, `TrickSessionFragment`, `LevelResultScreen` и
`ResultSolutionDialog` нужно учитывать отдельно от Navigation Graph. В JSON есть
их источники. Глубокие параметры статистики, решения и таблицы могут читаться
напрямую из Bundle и не объявляться в XML-графе.

Оценка приложения, поддержка, Instagram, системное согласие, покупки, Game Center
и выбор файла — внешние действия. Кнопка `b_ios` в текущем Android вызывает
`startInstagram()`, а не отдельную игру: переносить вымышленный режим нельзя.
Отправка письма или публикация в рамках этапа 1 не выполняются.

## Режимы и идентификаторы

| Семантика | Android | Старый iOS | Game Center старой iOS |
|---|---|---|---|
| Обычная игра | `MODE=0` | `GAME_MODE_SINGLE=1` | `lb_game_single_free` |
| Минута | `MODE=1` | `GAME_MODE_MINUTE=2` | `lb_game_minute_free` |
| Скорость | `MODE=2` | `GAME_MODE_SPEED=3` | `lb_game_speed_free` |
| Без времени | `MODE=3` | `GAME_MODE_NO_TIME=4` | `lb_game_noTime_free` |
| Ежедневная игра | `MODE=4`, отдельный маршрут | Нет | Старого ID не найдено |
| Конкретный приём | Отдельный `game_training_fragment` | `GAME_MODE_TRAINING=5` | Общий прогресс: `lb_tricks_levels_free` |
| Заучивание | Отдельный `game_by_heart_fragment` | `GAME_MODE_BY_HEART=6` | Общий прогресс: `lb_byHeart_multiplication_levels_free` |

Для общего количества решений найден `lb_total_solved_free`. Новые режимы и
подробная статистика не получают произвольно выбранный старый leaderboard ID.
Android-графики 1–4 и legacy-графики 1–4 соответствуют четырём одиночным режимам;
Android-график 5 — серия дней, прямого старого аналога нет.

`GameTypeFragment` передаёт случайный набор `TRICK_ID=-1`,
`GameTypeTrainingFragment` — выбранный `TRICK_ID=-2` в те же четыре режима.
Дополнительные значения каталога: заучивание `-3`, RTM `-4`. Значения-указатели
не являются ID сохранённого приёма и не подставляются в миграцию уровней.
Для заучивания передаются также `BY_HEART_NUMBER` и `BY_HEART_LEVEL`.

В legacy найдено 107 именованных ID приёмов. У 105 есть точное совпадение имени
константы Android, и у всех 105 числовые ID отличаются. Пример: сложение
`1001 → 1`, вычитание из 1000 `2002 → 11`.

Эти 105 пар — кандидаты по имени, а не уже выполненная миграция. До записи данных
надо сверить содержание приёма, нумерацию уровней и значение полей результатов.
Две legacy-константы пока без точного совпадения:

- `trick_square_number_between_90_and_99_id = 5016`;
- `trick_2_root_id = 7001`.

В Android есть похожие по смыслу `trick_square_number_between_11_and_99_id = 17`
и `trick_square_root_id = 24`, но автоматическое объединение пока не разрешено
анализом. Нераспознанный старый прогресс сохраняется до отдельного решения.
Полный список кандидатов и несовпадений записан в JSON.

На этапе 4 обе пары уточнены по генераторам: `5016 → 17`, `7001 → 24`.
Рабочая карта `Progress/LegacyTrickMapping.json` содержит все 107 пар; детали и
различие диапазона первых уровней приведены в LEGACY_PROGRESS.md. Перечень выше
и исходный JSON-инвентарь сохраняют результат первоначального анализа.

## Сохранение данных старых пользователей

Источник истины для совместимости — `AppDelegate.swift`, `MyCoreData.swift`,
`MyDefaults.swift`, `Main.createDatabase()` и обе версии `.xcdatamodel`.

- Идентификатор старого приложения: `com.antoni.mathtricks.free`. На этапе 1 в новом
  проекте общий / simulator Bundle ID отличался от `iphoneos`, а deployment target
  был 26.5. На этапе 2 Bundle ID согласован, минимальная iOS установлена в 15.0;
  исходный JSON-инвентарь сохраняет исторические значения этапа 1.
- Старый контейнер: `NSPersistentContainer(name: "Math_Tricks")`; URL хранилища
  не переопределяется в исходнике. При реализации нужно сохранить имя модели,
  совместимые версии и фактический URL, а не угадывать его по новому имени приложения.
- Существуют `Math_Tricks.xcdatamodel` и `Math_Tricks v2.xcdatamodel`;
  `.xccurrentversion` выбирает v2. Добавление `Graphs` — не единственное отличие:
  менялись также настройки представленных классов сущностей.
- `Tricks`: `id`, `name`, `checked`, `status`, `status_fixed`.
- `Tricks_Levels`: `id`, `parent_id`, `rating`, `score`, `status`.
- `ByHeart_Multiplication`: `id`, `parent_id`, `rating`, `score`, `status`.
- `Graphs`: `id_game`, `date`, `score`.
- Многие старые числовые поля — optional Int16, статусы — Boolean. Новые счётчики
  и новые модели нельзя без проверки читать как тот же тип или безусловно сужать.
- Сохранить ключи UserDefaults: монеты, общее число решений, обычные и выбранные
  рекорды, текущую / максимальную сложность, победы игроков, длину партии,
  раскладку, тему, звук, вибрацию, маркер `COREDATA_VERSION_OLD`.
- Отсутствие новой настройки не означает отсутствие старой базы.
  `Main.createDatabase()` в legacy использует маркер UserDefaults для первой
  загрузки; перенос не должен вызывать его инициализацию поверх существующих данных.
- Перед миграцией нужна согласованная резервная копия хранилища с его журналами;
  изменения записываются атомарно, повторный запуск миграции не дублирует прогресс.
  Ошибка открытия не должна приводить к удалению старого хранилища.
- Android SQLite не подменяет старую Core Data. Его дополнительные данные
  (подробная статистика, облачные профили, серия дней) вводятся отдельной миграцией.
- Версия старого проекта в файлах — 1.7, build 9; это не доказательство последней
  опубликованной версии. Перед выпуском потребуется проверка реального обновления
  и имеющихся пользовательских хранилищ. На этапе 1 оно не выполнялось.
