# Этап 16 — два игрока

`MultiplayerSetupViewController` задаёт 5…35 шагов (с шагом пять), один из трёх
способов ввода и соревнование/совместную игру. Каталог открывает тот же экран
с отмеченными приёмами; главное меню — со случайным Android-набором.

`MultiplayerSession` хранит два независимых GameSession и общее состояние.
В соревновании правильный ответ сдвигает шкалу к игроку на один шаг, ошибка
вариантов/верно-неверно — в обратную сторону. В совместной игре 20-секундный
таймер общий, ответ любого игрока возобновляет полный интервал, очки соответствуют
оставшемуся времени. Числовой неверный префикс не имеет штрафа выбора.

`PlayerInputBoard` даёт две независимые зоны, верхняя/левая повёрнута к другому
игроку. Поворот меняет ось размещения и не пересоздаёт сессию. Очередь ввода
сохраняет действия второго игрока во время записи принятого ответа; устаревшие
нажатия на уже сменившийся пример отбрасываются.

SQLite user_version=3 добавляет multiplayer_sessions. Запись результата, монет,
общего количества и побед атомарна. Отдельный постоянный маркер победы исключает
повторный учёт при повторном сохранении завершённой партии. Сохранённую партию
можно продолжить из главного меню на паузе. Пауза/фон останавливают общий таймер.

Проверка: Debug generic iOS без подписи — успешно. Тесты, установка и запуск
не выполнялись. Настоящее одновременное нажатие и геометрия двух зон требуют
ручной проверки пользователем на этапе 24.
