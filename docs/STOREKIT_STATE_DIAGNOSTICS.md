# Обновление PRO и диагностика StoreKit

Переустановка сама по себе не доказывает, что причиной был RAM-флаг приложения.
Для воспроизведённого пользователем случая нет журнала транзакций с телефона.

В коде был возможен иной порядок завершения параллельных проверок при запуске,
возвращении приложения, открытии окна PRO и восстановлении. Более ранняя проверка
могла закончиться позже новой и записать своё состояние последней.

## Изменения в ios/Math_Tricks

- `Math_Tricks/Services/AppPurchases.swift`, `refreshEntitlements`: проверки выполняются
  последовательно, каждый вызов дожидается собственного чтения StoreKit. Очередь
  очищается после завершения последнего запроса.
- `readEntitlements`: доступ вычисляется заново по проверенным транзакциям
  remove_ads_v1 типа non-consumable. Из результата исключаются транзакции,
  отзыв которых уже подтверждён StoreKit в текущем сеансе.
- `start`: обработчик Transaction.updates учитывает revocationDate и не позволяет
  устаревшему снимку снова открыть ту же отозванную транзакцию. Новая действительная
  покупка обрабатывается по её transaction ID; актуальное подтверждение StoreKit
  может снова разрешить соответствующую транзакцию.
- `log`, `restore`: в Debug добавлены строки с префиксом `StoreKit PRO`, причиной
  проверки, средой покупки, transaction ID, датами покупки/отзыва, результатом PRO,
  значением simulatePro и ошибкой AppStore.sync, если она возникла.
  Чек, токены, пароль и email в журнал не выводятся.
- `Math_Tricks/Shell/AppRootViewController.swift`: проверка при возврате приложения
  помечается причиной active.

Автоматического AppStore.sync при старте не добавлялось: Apple требует вызывать
его по явному действию пользователя, поскольку он может запросить вход.
[Документация Apple](https://developer.apple.com/documentation/storekit/appstore/sync()).

## Как проверить на телефоне

1. Запустите обновлённую Debug-сборку из Xcode без удаления приложения.
2. Проверьте `simulatePro = false` в AppConstants.swift.
3. Повторите покупку и очистку истории именно этого Sandbox-аккаунта.
4. Вернитесь в приложение; для отдельной проверки синхронизации нажмите
   «Восстановить покупки».
5. Если PRO остаётся активной, откройте консоль Xcode и отфильтруйте строки
   по `StoreKit PRO`. Передайте строки после возврата и восстановления.

`purchased=true` с указанной проверенной транзакцией означает, что StoreKit всё ещё
вернул её в текущих правах. `purchased=false` при сохранённом интерфейсе PRO
указывает на необходимость проверить обновление UI или simulatePro.
Окончательный вывод о причине делается по этому журналу.

## Вход в аккаунт и публикация

Используется StoreKit 2 / Product.purchase(). Development-сборка из Xcode использует
Sandbox и при первой покупке может запросить вход в тестовый аккаунт. После
публикации будет использоваться производственная среда App Store и обычный аккаунт
покупателя. Apple и там может запросить вход или подтверждение оплаты; отсутствие
запросов аутентификации не гарантируется.
[Sandbox у Apple](https://developer.apple.com/documentation/storekit/testing-in-app-purchases-with-sandbox).
